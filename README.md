# MiniDSP — 3-hour AI Developer Challenge (simplified)

**Objective:** Build a working, tested, documented MiniDSP web app using two GitHub Copilot chats and human judgement. This is a competition, not a compliance paperwork exercise.

## The entire workflow
1. Open the project in VS Code. Open GitHub Copilot Chat 1 in Ask mode (Instructor). Paste `START_HERE_INSTRUCTOR.md`.
2. Instructor proposes a small next task and gives a copy-ready prompt.
3. Paste that prompt into a separate GitHub Copilot Chat 2 in Agent mode (Developer). Agent implements, tests and records progress.
4. Paste Agent's response into Instructor. Instructor challenges assumptions, code, tests, security and gaps; gives a focused follow-up if needed.
5. Repeat until working; the human developer orchestrates, reviews and decides what to approve and when to commit/deploy.

**Don't paste raw uploaded file content, credentials or personal data into either AI chat.** Only synthetic training files may be used.

## Files
- `START_HERE_INSTRUCTOR.md` — paste once into Chat 1
- `START_HERE_DEVELOPER.md` — paste once into Chat 2, before its first task
- `PRODUCT_BRIEF.md` — functionality, safety and acceptance criteria
- `CHALLENGE_TIMELINE.md` — timeboxes and priority
- `DESIGN_REFERENCE.md` — facilitator fills in actual design-system paths and live URL
- `WORK_LOG.md` — Agent maintains short, honest progress/test/decision log
- `LEARNINGS.md` — Agent helps developer capture lessons
- `DEVELOPER_SCORECARD.md` — generated by the Agent at the end of the challenge only
- `FOR_SUNJEEV.md` — setup checklist and facilitator instructions
- `DEVELOPER_QUICK_GUIDE.md` — one-page instructions
- `tests/fixtures/` — starter synthetic files; optional withheld acceptance pack provided separately

## Current workspace status

This workspace includes a minimal Next.js + TypeScript scanner and Supabase email/password auth flow. Cookie-backed middleware protects the scanner and scan API; login and signup pages render without Supabase credentials, but actual account creation and login require local Supabase project configuration. The current scan flow accepts CSV/TXT in memory, validates file type/size/UTF-8, classifies content server-side, and returns masked aggregate findings. Original content is not persisted or logged.

Copy `.env.example` to `.env.local` and set the Supabase project URL and anon key locally to enable live auth. Never commit `.env.local` or share keys in chat. The owner-scoped scans/findings migration is in `supabase/migrations/`; it has not been applied to the hosted project, and scan persistence is not yet wired into the app.

Run `npm install`, `npm run dev`, `npm test`, `npm run lint`, or `npm run build` from the project root. Unit tests cover all 30 synthetic acceptance fixtures. With the app running, `npm run test:smoke` checks that login/signup render, unauthenticated scanner access redirects, and the scan API denies unauthenticated requests.

Stop `npm run dev` before `npm run build`; both commands use `.next`, and running them concurrently can corrupt the local development output. Restart the dev server after the build to continue using the app.

This is not yet the complete SaaS described above: live Supabase signup/login, applying and exercising database RLS, scan persistence/history, dashboard, filtering, safe CSV export, Git hosting, and deployment are not implemented or verified. `DESIGN_REFERENCE.md` identifies the supplied local Lepidus guide; the live component rendering remains unverified. Use synthetic data only.
